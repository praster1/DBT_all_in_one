# 마당마켓 설계·운영 문서 묶음

다음 파일은 같은 교재 사례를 팀의 관리 문서로 옮긴 예시다. 실제 회사 정책이나 운영 승인 기록이 아니다. 담당자의 실명·연락처·운영 계정·비밀정보는 넣지 않았다.

| 문서 | 목적 |
| --- | --- |
| [아키텍처 결정](adr-001-architecture.md) | 후보·채택·보류·재검토 조건 |
| [데이터 계약](data-contract.md) | grain·상태·단위·정정·품질 경계 |
| [계층 정책](layer-policy.yml) | L0~L3 소유권·통과 조건·발행 규칙 |
| [버스 매트릭스](bus-matrix.md) | 공통 차원과 업무별 사실의 연결 |
| [운영 runbook](operations-runbook.md) | 진단·재시도·backfill·발행·복구 |
| [공개 모델 변경](change-policy.md) | 의미·스키마·물리 위치 변경의 분리 |
| [검증 수준](capability-matrix.md) | 실행된 것과 설명만 제공한 것 |

YAML은 운영 설계 문서다. dbt가 자동으로 읽어 권한·발행을 강제하는 내장 설정은 아니다. 실제 통합 구현 전에는 사용하는 엔진과 조직 정책으로 검증한다.
